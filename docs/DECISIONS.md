## D-001：工作规范生效

- **日期**：2026-11-16
- **决定**：本仓库执行 [`AGENTS.md`](../AGENTS.md) 与 [`docs/PROCESS.md`](PROCESS.md) 的角色互斥规范；同一 agent 在同一阶段不得承担组织、设计、开发、测试、审计中的两项及以上。
- **后果**：自审阶段无效；Auditor 必须独立；没有角色矩阵的任务卡不得开工。

## D-002：会话不是仓库角色，分工由阶段任务卡记录

- **日期**：2026-11-16
- **决定**：仓库决策只记录跨会话有效的规则与方向。某个会话承担什么角色，不写入本文件；由 `docs/tasks/<stage>.md` 的角色矩阵记录。
- **理由**：工作区可同时存在多个会话。把“本会话范围”写成长期决策，会造成虚假的永久所有权，并让其它会话无法接续。
- **后果**：角色可按阶段轮换；任何会话在同一阶段内不得承担两类及以上角色；Document Manager 可与 Work Organizer 合并，但不得与设计/开发/测试/审计合并。
- **修订**：原 D-002 把“当前会话范围”写成仓库决策，已作废；编号保留，避免下游引用断裂。

## D-003：Channel 采用模块化预设

- **日期**：2026-11-16
- **决定**：
  - 预设 A「内心之声」：主角的内心想法与说出的话进入用户视野；用户可主动窥视主角状态与行动；对话主要以内心想法而非语言进行。**先做**。
  - 预设 B「梦境之声」：用户默认全知视角，可看各地区概况与重要角色行动，可让角色进入 world 时停的梦境。**暂缓开发**。
  - 预设 C「物件通信」：依托某种物体存在的通信形式。**暂缓开发**。
  - A/B/C 是**默认组合**，不是硬编码；用户应可自行选择、搭配任意通信形式。Channel 必须模块化。
- **边界**：旧 PRD 的 D6（观察面板不显示思绪）与 R-CH4（信道必须会坏/暴露）不作为需求权威，属待重写草案。

## D-004：世界卡 / 提示词模块是独立模块

- **日期**：2026-11-16
- **决定**：提示词模块，更严格地说是**世界卡模块（World Card）**，是独立于“世界”和“角色”的模块；它与角色、世界联动，但不得把其内容硬编码进世界或角色。**限制提示词属于该模块的一部分**。
- **后果**：后续设计需要把世界卡作为独立模块处理；当前不设 WC 任务卡，待架构设计完成后再建。

## D-005：内容框架不提供实际服务

- **日期**：2026-11-16
- **决定**：
  - 框架不提供内容分级/审核服务；默认不做静默过滤。
  - 可选提供限制类提示词模块，但限制提示词属于世界卡/提示词模块，不是核心机制。
  - 世界观文本可以承载相同的限制功能。
  - 优先做**更 easy 的世界/角色提示词编写方案**。
  - 对“D 或 C”：以不内置服务为底线，保留用户自定义内容 envelope 的扩展位；具体默认值由设计会话决定。
- **后果**：R-11 不再以“内容审核清单”为 G6 门；改为“声明边界 + 宿主策略 + 无静默过滤验证”。

## D-008：World Card 在 World / Character 之后推进

- **日期**：2026-11-17
- **决定**：World Card（WC）不在 World / Character 之前推进。先分别完成世界与角色的设计与实现，再推进 WC。WC 不阻塞这两条线；World / Character 设计不得以“WC 未定”为阻塞理由，只定义对 WC 的接口假设。
- **现有草稿**：旧 WC 讨论稿已清理，不作为输入；WC 重开时从架构设计重新开始。
- **后果**：当前不设 WC 任务卡；World / Character 设计也不得以“WC 未定”为阻塞理由；WC 重开需用户明确指令。
