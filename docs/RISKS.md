## 2. 最高优先级三条

1. **R-01 合并变重写**：M1/M2 的每个 PR 必须证明两 demo 仍绿；共享层不反向依赖 demo。
2. **R-04 Channel 语义走样**：Channel 的原文/延迟/暴露测试必须先于 UI；没有这三个测试，不做消息界面。
3. **R-08 7 天拖期**：M5 后期就开稳定分支预演，不要等 M6。

## 3. 风险升级规则

- 触发信号出现一次：记录到周报，任务卡标黄。
- 连续两次或阻塞 gate：升级为阶段阻断，先走 DEVELOPMENT_PLAN 的失败分支。
- 风险被消除：保留条目，标 `closed`，写证据；不删除历史。
