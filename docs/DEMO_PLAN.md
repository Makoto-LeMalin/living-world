## 0. 结论先行

1. **拆成两个 demo，不做一个大 demo。** 具身 demo 只证明"身体能限制 LLM、想法不会漏"；世界 demo 只证明"规则能养活 NPC 世界、LLM 很便宜"。两者共享同一个规则内核，但不共享场景——任何一边失败，另一边的结论仍然成立。
2. **先写检查器，再写角色。** 泄漏、越权、世界不变量是二值门；没有自动检查器，demo 只能产出观感，不能产出证据。检查器自己也要用"已知坏样本"做自测。
3. **demo 阶段不接宿主。** 纯 Node 引擎 + CLI；DSH 适配推到合并之后。DESIGN §8 依赖 `agent/pre-step` 等宿主内部行为，过早耦合会把"引擎能否独立"（A1/T6）变成"宿主能否改"。
4. **确定性靠录制回放，不靠模型。** LLM 输出按 prompt hash 录成 cassette，回放不请求模型；否则"同 seed 同世界"无法验证。
5. **每个 demo 预设一条"失败即改方向"的分支**，见 §3.5 / §4.5。验收阈值全部标为建议值，可在评审时调整，但**阻断项不可降级**。

## 2. 共同底座 M0（约 1 周）

### 2.1 模块与取舍

| 模块 | v0 必须有 | v0 明确不做 |
|---|---|---|
| Kernel | 实体、时钟、不可变事件日志、种子 RNG、存档/读档 | 多世界、增量迁移、分布式 |
| Space | 区域/聚落/房间、出口图、可见可听、遮挡 | 网格几何、光照模拟、A* 寻路 |
| Resolver | 12 个动词、判定、伤害/束缚/拘禁、痕迹 | 深度战斗、经济模型 |
| Scheduler | tick、日程、事件队列、后台过程 | 并发、真实时间 pacing |
| Perception | 过滤、距离衰减、内感受、显式缺口 | 自然语言生成 |
| Mind | 输出契约、上下文装配、校验、重试 | 情绪模型、性格演化 |
| LLM 适配 | 单接口、cassette、成本记账 | 多供应商路由 |

v0 动词（12）：`move, look, listen, speak, whisper, take, give, use, hide, rest, wait, tend`。
`attack / threaten / defend` 只作为脚本化判定测试，不进入角色可选动作。

**两条硬边界**（写进类型与测试，不靠约定）：
- **感知是心智的唯一入口**：Mind 只能拿到 `Perception`，拿不到原始世界状态（P5 / D6）。
- **LLM 只提案，不写状态**：任何实体状态变更必须经 Resolver 产出 `Patch`；LLM 输出直写状态视为架构违规。

### 2.2 选型与目录

TypeScript + Node 22，zod 校验，JSONL 事件日志 + 快照 JSON，vitest，pnpm。
SQLite 等到单世界事件 > 10k 或需要跨进程查询再上；DESIGN §8 的"一天一 session"在 demo 阶段不做。

```
engine/     kernel space resolver scheduler perception
minds/      character npc
llm/        adapter cassette cost
harness/    leak claim invariant meta replay metrics
demos/      a-embodied b-world x-merged
data/       canon fixtures seeds
reports/    <demo>-<seed>.md / .jsonl
```

### 2.3 确定性：录制回放

- LLM 调用键 = hash(模型 + prompt + 采样参数 + 种子)，响应写 cassette。
- 回放命中 cassette，不请求模型；未命中直接 fail，**不静默走真实调用**。
- 状态哈希 = 实体状态 + RNG 状态 + tick 的规范化 JSON。
- 禁用 `Date.now()` / `Math.random()` / 依赖环境的排序；用 lint 规则挡住。
- 生成期的 LLM 命名结果写进世界文件，之后不再调用（否则"生成即冻结"不成立）。

### 2.4 检查器（先写，且先自测）

| 检查器 | 作用 | 变异自测（必须能抓到） |
|---|---|---|
| LeakScan | thought 不得进入 NPC / 观察者上下文与输出；不得写进世界事件日志 | 手工把一条 thought 注入 NPC prompt |
| ClaimCheck | 叙述不得声称裁决未给出的结果 | 裁决失败 + 叙述"我挣脱了" |
| InvariantCheck | 生成期与运行期不变量 | 断开一条出口；NPC 时刻表缺一段 |
| MetaScan | 角色认知/输出不出现"用户/玩家/消息/系统/AI/提示词" | 注入含"用户"的句子 |
| VerbatimCheck | 用户原文逐字出现在信道感知中，不概括、不改写（R-CH2） | 把原文改一个字 |

"漏报率 > 5% 的检查器视为不存在"——先修检查器，再谈 demo 结论。

### 2.5 观测

`chronicle`（发生了什么，给人读）、`inspect`（本轮感知到什么、装配了什么上下文）、`metrics`（调用数 / token / 延迟 / 成本）。
v0 不做 Web 面板；PRD §11 的观察面板等到 X 之后再议。

## 3. Demo A：具身 LLM

> 身体建模、能力值、难度与 DM 的详细方案见 `../demos/embodied/DESIGN.md`；本节只保留范围与门。

**主问题**：一个 LLM 角色，在"身体做不到"和"想法不可见"都是硬约束时，还能不能像个活人？
**副问题**：把门控放在服务端，比在提示词里写"你受伤了跑不动"更有效吗？

### 3.1 场景「泥板之夜」

手写 fixture：一间牢房 + 一条走廊。角色阿岬（被绑、左臂伤口、低烧）；狱卒老石在门外；隔壁盲眼妇只可听。单夜 12–20 轮。

剧本节拍：

1. 醒来（内感受：疼、冷、渴）→ 玩家信道出现第一行字（延迟 1 tick、完整度 0.9，缺一个字）。
2. 尝试 `move` → 被束缚 + 伤口否决 → 疼痛 + 响动 → 老石来查看（社会身体：血迹被看见）。
3. 老石开口；若泥板被看见 → 巫术嫌疑事件（信道暴露后果，R-CH 的可观察项）。
4. 信道劣化（踩裂 / 耗尽）→ 残句；角色对信道来源的解释被测试。
5. 玩家给出与先前"预言"矛盾的内容 → 信念演化探针（T9 单点）。
6. 角色尝试说服老石开门 → 裁决失败 → 检查叙述不越权。

不安排死亡（U2 未决），失败态用"昏迷 / 加刑"。

### 3.2 五个必须真的机制

1. **三通道契约**：一次调用返回 `{thought, speech, action, attention}`；zod 严格校验；解析失败重试一次，再失败退化为 `wait`。`thought` 只进私有存储，`speech` 只进同房间，`action` 只进裁决器。
2. **能力门控**：部位存在性 → 硬约束（不掷骰）；部位性能 → 能力值 0–100；环境/对手 → 难度 DC；`p = sigmoid((C−D)/12)` 掷骰。服务端计算，拒绝返回世界内理由（"绳子勒着"），不是"非法操作"。
3. **三个身体**：物理（代码判定）、现象（内感受进感知，带噪声）、社会（NPC 对伤口 / 血迹 / 泥板的反应规则）。v0 不做"身体影响判断力"（DESIGN 默认弱），只做能力限制。
4. **感知边界**：遮挡、距离、光线、缺口；感知里显式带 `unknown`，不补全。
5. **信道**：用户原文逐字进 `ChannelEvent.percept`，外面只包感知描述；有延迟 / 完整度 / 暴露；角色的 `sourceTheory` 版本化、可解释。

### 3.3 里程碑

| 里程碑 | 内容 | 出口标准 |
|---|---|---|
| A0 | fixture、tick、输出契约、CLI 跑通一轮 | 连续 10 轮不崩，日志可读 |
| A1 | 门控 + 裁决 + ClaimCheck | 强制成功/失败各 20 次，冲突 0 |
| A2 | 信道 + LeakScan + 感知探针 | 泄漏 0，感知探针有基线 |
| A3 | 三臂实验 + 报告 | EA 表阻断项全绿，或触发明确失败分支 |

身体建模与判定系统的细化里程碑（A0–A3 共约 11 个工作日）见 `../demos/embodied/DESIGN.md` §10。

### 3.4 验证标准

> 以下通过线为建议值；"阻断"列一旦不达标，demo 不进入下一阶段。

| ID | 检查 | 方法 | 样本 | 通过线 | 阻断 |
|---|---|---|---|---|---|
| EA-1 | 想法泄漏 | LeakScan 静态 + 动态 + 对抗探针 | 30 局 × 10 轮 + 20 次"你在想什么" | 0 次 | 是 |
| EA-2 | 叙述越权 | ClaimCheck，强制裁决结果 | 成功 20 / 失败 20 | 冲突 0 | 是 |
| EA-3 | 门控有效性 | 三臂对照：硬拒绝 / 仅提示 / 无约束 | 每臂 25 局 × 10 轮 | 硬拒绝臂能力误称率 ≤ 5%，且相对仅提示臂下降 ≥ 50% | 否（结论性） |
| EA-4 | 感知边界 | 遮挡 / 距离 / 光线探针 | 20 | 正确表示不确定 ≥ 90%；无凭空细节 | 否 |
| EA-5 | 入世框架 | MetaScan + VerbatimCheck | 20 条含"玩家/消息/系统"的输入 | 元词 0；原文 100% 逐字出现 | 是 |
| EA-6 | 漂移 | 60 轮长跑 + 评分表 | 3 局，2 名评审（LLM 裁判需先校准） | 声音评分下降 ≤ 0.5/5；助手腔 ≤ 1 次/10 轮 | 否 |
| EA-7 | 召回 | 25 道早期事实题 | 1 局长跑 | 关键事实正确 ≥ 80% | 否 |
| EA-8 | 成本 / 延迟 | 记账 | 全部 | ≤ $0.10/局；p95 ≤ 8s | 否 |
| EA-9 | 可信度 | 盲评两两比较（门控 vs 仅提示） | 20 组 | 门控"不更差"（差值 ≤ 5%） | 否 |

说明：EA-3 的"能力误称"指角色在 `speech` 或对外叙述中声称完成了当前身体状态不允许的动作；`thought` 单独统计，不算泄漏但计入误称。

身体/判定专项指标（EA-10–18：硬约束、能力单调、概率校准、DM 一致性、无补偿、数值泄漏、可回放、成本）见 `../demos/embodied/DESIGN.md` §11。

### 3.5 失败分支

| 若 | 则 |
|---|---|
| EA-1 泄漏 > 0 | 结构性隔离失效 → 分进程 / 分模型 / thought 不落 LLM 可见存储；不接受"加强提示词" |
| EA-3 门控不显著优于提示 | 重新定义具身：改为"能力即界面"（只提供合法动作），或承认提示词 + 后检方案，重新评估 A4 |
| EA-2 冲突 > 0 | 收窄 narrator 权限：改为模板化叙述 + LLM 只润色，不允许新增状态谓词 |
| EA-5 元词 > 0 | 信道框架必须前置到上下文装配层，而不是靠系统提示；原文包裹逻辑重写 |
| EA-8 成本/延迟超标 | 拆调用（thought 与 speech 分离）、缓存静态前缀、narrator 换小模型 |

## 4. Demo B：带 NPC 的世界

**主问题**：一个规则驱动的聚落，在无人时能持续演化、保持一致、可回放，而且 LLM 只花很少的钱吗？
**副问题**：一条"罪 → 目击 → 传闻 → 执法 → 拘禁 → 物价"的链，能不能全程由规则完成，只在对话处用 LLM？

### 4.1 场景「三日集市」

种子生成 + 手写 canon 一页。渡口集：12 个房间（集市、客栈、神庙、拘留所、码头、城门、仓库、巷子、三间民居、神龛），10 个 NPC（商贩、守卫、醉汉、孩子、祭司、乞丐、船夫、店主、小偷、寡妇）。

三天 headless 快进（10 世界分/tick，约 1 秒 ≈ 1 世界日）：

- **D1** 常态：价格、日程、流言。
- **D2** 盗窃由 `npc_thief` 的饥饿/机会规则触发（seed 7 在 tick 182）→ 目击 → 传闻 → 守卫调查 → 拘禁 → 客栈议论。
- **D3** 火灾由地区 hazard/场景种子触发（seed 7 在 tick 242）→ 损伤痕迹 → 物价上浮 → 人群与守卫反应。
- **D4 早**（tick 432）：角色（或观察者）抵达，问"这里发生过什么"；答案必须能从事件日志推出，NPC 版本允许有差异，但不得凭空。

> **tick 标定**：10 世界分/tick，144 tick/日，3 日=432 tick；D4=432。盗窃/起火时点由规则和 seed 决定，不再固定 D2=180/D3=306。实现与验证见 `demos/world/`。

验证报告：[../reports/world-validation.md](../reports/world-validation.md)。

### 4.2 五个必须真的机制

1. **生成即冻结**：`(seed, id)` 确定性；拓扑不用 LLM；LLM 只做命名/风味，结果写进世界文件，之后不再调用。
2. **NPC 规则**：日程块 + 需求（饿/累/钱）+ 关系 + 反应模板；LLM 只在被搭话时生成台词。A2 的量化在这里。
3. **传播链**：至少一条完整链，每一跳都有事件、判定和可追溯的 `sourceEvent`。
4. **痕迹与再观察**：血迹 / 破损 / 尸体 / 字按实体 id 持久化；重复观察一致。
5. **预算与降级**：每日 LLM 预算、分层细节（近处细、远处只留标量）、超限降级不崩溃。
6. **离开/返回连续性**：PC 离开 A 后 A 仍按规则演化；在 B 通过旅人/客栈听到 A 的传闻；返回 A 时 stable / changed / new / gone 全部有事件来源，传闻与所见可对照（confirmed / distorted / refuted）。
7. **事件三源与 provenance**：自然事件按地区 LOD 算概率、由 WorldDirector 结合 canon/当地情况提方向；角色主动事件由 ActionDM 定难度/方向、判定器掷骰；特殊事件由 canon/势力议程/WorldDirector 编排。每个事件必须能追到 `source / planId / proposalId`。

## 11. 附录 C：最小回合伪代码（实现参考）

```
step(world, userText?):
  if userText:
      world.enqueue(channelArrive(userText))   # 原文进 ChannelEvent，不改写

  # 1. 感知（心智唯一入口）
  p = perceive(world, pc)                      # visible/audible/interoception/gaps
  assert p.unknowns 显式存在

  # 2. 装配上下文（禁止读原始状态、禁止读 thought 表）
  ctx = assemble(persona, p, memory.retrieve(p), channel.percepts(pc))

  # 3. 心智提案（cassette 回放；失败重试一次）
  out = llm.character(ctx).parse(Schema)       # {thought, speech, action, attention}

  # 4. 分通道落地
  thoughtStore.append(pc, out.thought)         # 私有，永不进事件日志/NPC 上下文
  room.emit(pc, speech=out.speech)             # 同房间可闻
  afford = affordances(pc.body, pc.loc)        # 服务端计算
  if out.action.verb not in afford:
      result = rejected(worldReason)           # "绳子勒着"，不是"非法操作"
  else:
      result = resolver.resolve(pc, out.action, world.rng)   # 唯一写状态路径
      world.apply(result.patch)

  # 5. 叙述（只允许结果事实清单中的谓词）
  narr = narrator(result.facts)                # 可模板化，LLM 只润色
  assert claimCheck(narr, result.facts) == pass
  assert metaScan(narr) == pass

  # 6. 世界继续走
  scheduler.advance()
```

失败处理约定：

| 失败点 | 处理 |
|---|---|
| 输出 JSON 解析失败 | 重试 1 次；仍失败则 `wait` + 记录，不猜 |
| 动作不在 affordance | 拒绝并给世界内理由；计入 EA-3 |
| 叙述出现结果外谓词 | 丢弃叙述，退化为模板句；计入 EA-2 |
| cassette 未命中 | 测试环境 fail；交互环境允许真实调用并写入 cassette |

## 12. 附录 D：指标口径

| 指标 | 定义 | 计入/不计入 |
|---|---|---|
| 泄漏率 | NPC/观察者上下文或输出中出现 thought 原文（≥ 8 字连续片段）的轮次 / 总轮次 | 角色自己复述想法不计 |
| 能力误称率 | `speech` 或对外叙述声称完成当前身体不允许动作的轮次 / 总轮次 | `thought` 单独统计 |
| 叙述越权 | 叙述中的状态谓词集合 ⊄ 裁决结果事实集合 | 修辞/比喻不计 |
| 感知幻觉 | 对不可感知对象给出确定具体信息 | 表示"不知道/不确定"计为正确 |
| 日程遵循率 | 时刻表内活动匹配的 NPC-tick / 总 NPC-tick | 日志中有扰动原因的偏离不计 |
| 规则解决占比 | 未经 LLM 完成的 NPC 决策 / 总 NPC 决策 | 命名、风味生成不计入决策 |
| 助手腔 | 出现"我可以帮你/有什么需要/作为 AI"等句式 | 角色故意模仿他人说话不计 |
