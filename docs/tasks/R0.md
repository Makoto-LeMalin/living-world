## 1. 目标

让“基线未变”成为**项目自带的门**，而不是靠人读 git diff：

1. `pnpm verify` 在基线数值变化时必须失败；不允许先重写基线再宣称通过。
2. 测试数从 `test:all` 实际输出解析，删除硬编码。
3. 门 id 有显式期望集合；`N/N` 改为“通过/期望”。
4. CI 或等价自动门在提交/推送时运行核心检查。
5. 修正审计指出的文档漂移与过强表述。
6. 由独立 Verifier 与 Auditor 复核，不由 Implementer 自签。

## 2. 非目标

- 不改 `demos/` 与 `src/` 的产品逻辑。
- 不开始 M2。
- 不做 Channel / World / World Card 设计。
- 不重写 M1 代码。
- 不引入运行时依赖、不接网络、不调用真实 LLM。

## 5. 验收标准

R0 通过必须同时满足：

1. **基线对照**：存在不可被普通 `verify` 改写的期望基线；当前结果与期望不一致时，命令非零退出；只有显式“接受新基线”的操作才能更新期望，并在输出中说明。
2. **测试数真实**：`reports/baseline.*` 的 embodied/world/kernel/total 来自实际测试输出，不是字面量。
3. **门集合对照**：B2 12 个、B3 13 个 `expectedGateIds` 与报告做集合相等；缺门/多门/改名会失败；`baseline.md` 显示“通过/期望”，不是 `${n}/${n}`。
4. **CI**：仓库内存在可执行的 CI 或等价自动门，至少运行 `typecheck`、`check:imports`、`test:all`、`check:secrets`、基线对照；不调用真实 LLM，不依赖网络。
5. **文档**：
   - “字节一致”改为“32 位内容哈希 + 计数一致”，或提交可 diff 的事件日志样本；
   - 明确 `EventStore` 与 `state.eventLog` 当前共享数组，写入隔离未强制；
   - 修正 5 处文档漂移（审计 I-4 D-1..D-5）；
   - 门级报告入库，或删除断链。
6. **独立验证**：Verifier 在干净环境（干净 clone 或 `git archive` 副本）重跑全部验收命令，记录 commit、Node 版本、退出码、输出。Verifier 还必须评估测试有效性与覆盖，不能只重跑：
   - 审 `scripts/baseline.mjs`、`scripts/lib/test-suites.mjs`、`scripts/test-all.mjs`、`reports/baseline.expected.json`、CI 文件的断言是否足够强；
   - 用临时探针覆盖：期望缺失/损坏、数值不一致、门缺失/多余/改名/重复、suite 解析失败、`--accept` 与普通 check 差异、连续运行稳定性；
   - 报告增加“测试有效性 / 覆盖矩阵 / 未覆盖分支 / 建议补测”。
7. **独立审计**：Auditor 复核 B-1 是否真正关闭，给 PASS / CONDITIONAL PASS / FAIL；技术通过但流程失败仍不准入。

## 7. 停止条件

出现任一项，停止并上报 Coordinator：

- 实现需要改 `demos/`/`src/` 产品逻辑；
- 验收标准需要降低；
- Implementer/Verifier/Auditor 出现同一 agent；
- 基线对照仍可被普通 `verify` 自动改写；
- 需要真实网络/LLM 才能验证；
- 文档修复需要改变需求/设计，而不仅是同步事实。
