## 1. 目标与边界

M1 只做一件事：**把两个 demo 已证明、且产品层必然重复的内核抽出来，行为不变。**

明确不做：

- 不统一角色运行时（M2）。
- 不拆 Compiler/DM/Resolver（M3）。
- 不接 Channel/Memory/Persona（M4）。
- 不引 SQLite/宿主（M5）。
- 不改事件 schema、不改 CLI 输出格式、不新增运行时依赖。

成功标准不是“代码更漂亮”，而是：**同 seed 的 B2/B3 事件日志与投影 hash 与 M0 完全一致。**

---

## 2. 模块划分

```
src/contracts/     跨层类型（P0 冻结，仍只依赖自身）
src/kernel/        时钟、RNG 分流、ID、规范化 JSON、快照/JSONL
src/space/         房间、聚落、路线、可见范围（纯结构）
src/world/         EventStore（只追加）+ Projection（事件→状态）契约
harness/           Replay 签名、Invariant 容器
engine/            最小原语（canonical JSON、mulberry32），供 kernel/llm/harness 复用
```

依赖方向不变：`host → app → 领域 → 基础设施`。新增的 `check:imports` 把以下规则变成门：

1. `src/` 不能 import `demos/`；
2. `src/contracts` 只能 import 自己；
3. `engine/` 不能 import `llm/`、`harness/`、`src/`；
4. `src/host` 不能带宿主类型（当前尚无 host，先留检查）。

`engine` 保留为**最小原语层**，`src/kernel` 是**项目级入口**：demo 与产品代码 import `src/kernel/*`，不直接依赖 `engine/*`。这样原语可以替换，而不用改所有调用方。

## 3. 关键设计

### 3.1 Kernel：把“可回放”变成默认

| 文件 | 职责 | 兼容性约束 |
|---|---|---|
| `src/kernel/clock.ts` | `ClockSpec`、`WorldClock`、`dayOf/tickOfDay/formatTick` | 既有 tick 语义与时间格式不变 |
| `src/kernel/rng.ts` | `stream/roll/chance/pick` | 同一 seed + 用途 + 参与键 → 同一序列 |
| `src/kernel/ids.ts` | `formatId/parseId` | `e_000001`、`f_00001`、`t_00001` 字节不变 |
| `src/kernel/canonical-json.ts` | `canonicalJson`、`hashCanonical` | 键排序与 8 位 hash 不变 |
| `src/kernel/snapshot.ts` | 快照信封、JSONL 读写 | `{version,snapshot}` + 2 空格缩进 + 末尾换行不变 |

设计取舍：

- `clock` 不读 `Date.now()`；宿主传 `realMs`。开发用 `stepped`，应用用 `realtime`（ADR-10）。
- RNG 不做全局状态；每次按用途分流，避免“多一个调用就改变后面所有随机”。
- ID 序号由世界状态持有，格式化只负责补零；不引入 UUID，保证日志可读、可 diff。
- 快照与 JSONL 的字节格式写成契约，因为它们是 M0 基线的一部分；换 SQLite 是 M5 的事。

### 3.2 Space：只做结构，不做剧情

`Space<R, T>` 只持有 rooms/routes，提供：

- `room/maybeRoom`、`placeOfRoom`、`roomsInPlace`（保留 canon 顺序）；
- `routeBetween`（双向）、`neighbors`；
- `scopeRoomIds(visibility, roomId)`：`private` 空、`room` 单间、`place/public` 同聚落；
- `validate()`：坏出口、坏端点、自环、重复路线。

世界层把可见范围映射成“在场者集合”时，仍按 **characters → crowds → pc** 的全局顺序过滤，保证 witness 顺序与 M0 一致。`public` 在当前世界语义里等同 `place`；如果未来要做跨聚落公开事件，改 `scopeRoomIds` 一处，不动调用方。

### 3.3 EventStore + Projection：拆开“记录”和“解释”

```ts
class EventStore<E extends { id: string; tick: number }> {
  append(event: E): E;
  all(): readonly E[];
  last(): E | undefined;
  find(id: string): E | undefined;
}

interface Projection<E> {
  apply(event: E): void;
}
```

`World.emit` 现在是：

```
构造事件（witness/fact/trace/id）
  → events.append(event)      // 只记录
  → projection.apply(event)   // World 自己实现
  → metrics++
```

`World.apply` 仍是领域投影，没有拆成多个 applier：M1 的目标是**隔离写路径**，不是重写投影。这样 EventStore 可以被 JSONL/SQLite/远程存储替换，而投影仍由世界层解释。

当前实现细节：`World` 把 `state.eventLog` 原数组传给 `EventStore`，二者共享同一引用；`append` 只是向该数组 push。因此“记录与解释分离”在**接口层**成立，**写入隔离尚未强制**；任何持有 `world.state` 的代码仍可绕过 `EventStore`。`test/event-store.test.ts` 的引用相等断言只锁定当前实现，不是长期契约。M2 若要依赖隔离，先改测试并实现只读视图/复制/注入存储。

### 3.4 Harness：回放与不变量共享

- `harness/replay.ts`：`eventSignature` 用规范化 JSON；`verifyReplays` 一次比较多份日志，返回 hashes 与 ok。B2 的重复回放改用它。
- `harness/invariant.ts`：`InvariantBuilder` 统一计数/收集错误；`duplicateIds`/`combineReports` 供各层复用。B2 的 canon 检查改用它，检查数仍为 64。

## 6. 已知边界与后续

- `World.apply` 仍是单个大投影；M5 若要换存储/做增量投影，再按事件类型拆 applier，不 ahead-of-time 拆。
- `Space` 只覆盖房间/路线/可见范围；感知的注意力、光线、遮挡仍在世界层，属于 M2/M3。
- `public` 暂等同 `place`；跨聚落公开是产品需求出现后的扩展。
- `src/contracts` 仍只有类型；M2 起把 `CharacterRuntime` 等契约接到实现。
- `check:imports` 是文本扫描（3 条规则、11 个文件），不做 TS 语义解析；发现绕过时再升级。
